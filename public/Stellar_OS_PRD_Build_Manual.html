1. 产品定位与核心设计哲学

Section 1: Product Positioning & Aesthetic Conventions

Stellar OS（星辰空间协同及融合社交资产系统）是一款基于 React 19 + TypeScript + Vite 的下一代高精多维地理信息聚合控制中心。系统以地理坐标空间（GIS Layer）为核心骨架，将群组即时端到端加密通信（E2EE）、家庭生命守护机制、学术研究日程以及多模态非结构化媒体资产管理进行无缝整合。在交互上，致力于为极客用户、科研小组和家庭单位提供极致精确、极高信息密度且物理触觉清晰的信息中枢。

1.1 Facebook 直角线框 UI 系统规范 (Anti-Slop Guidelines)

为坚决杜绝低质无规则的设计模板，整个 Stellar OS 强制执行统一的 Facebook Straight-Edge Line Frame UI 规范。其数学与视觉公式定义如下：

  • 色彩层次原则 (Color Scale)：基础画布背景统一为温暖低饱和的中灰色度 (#F0F2F5)；所有功能卡片、控制台模块采用纯白背景 (#FFFFFF)。
  • 直角边框规则 (Straight-Edge Border)：卡片与网格统一执行 border border-[#E4E6EB] 直角边框。若配置 hover 态，边框亮起过渡为 Facebook 经典品牌蓝 #1877F2，边角微弧度 rounded-md (限定 6px) 或纯直角，绝不使用 12px 以上的过渡圆角。
  • 极致数据密度 (High-Density Hierarchy)：取消任何不具备实际功能属性的插图与英雄文字。文字尺寸主体分布在 11px（注释标签）、12px（表项内容）、14px（正文）与 16px（模块标题），行高恒定为 1.5 倍，确保在一屏幕内呈现最大化的可操作状态。
  • 立体阴影深度 (Flat Depth)：禁止使用宽而柔和的扩散性阴影。统一采用极细致微弱的边缘暗影 shadow-2xs 或 shadow-xs，保持平面物理质感。

2. 核心功能模块详细 PRD 需求规格

Section 2: Multi-Module Detailed Functional Requirements

系统由 7 大平行协同模块和 1 个全局高保真物理宿主框架共同构成：

2.1 地理微聚类底图引擎 (MapView)

  • 多级省市自适应聚类：通过计算地标集合 of 经纬度，自动归类并计算出“甘肃省/兰州市”二级分组。支持地标计数器在地图底座上自适应叠加收缩。
  • 拥堵路况感知叠加 (Traffic Flow Overlay)：集成实时交通负荷率计算器，支持动态绘制主要拥堵干道（如兰州核心主干路、跨河大桥等），路况流通率降低至 35% 以下自动标识为红色重度拥堵。
  • 雷达隐身与防追踪 (Invisible Mode)：用户在主面板开启“隐身”后，客户端停止向任何地图图层更新位置，经纬度冻结在开启隐身瞬间，直至手动关闭。
  • 双击自定义地标 (Interactive Custom Marker Grid)：支持用户在 Leaflet 底图的任意位置双击，弹出新增地标面板，用户可指定类别（如“家庭”、“救援”、“星卡”）、设定地标标题、添加备注标签，并持久化到本地。

2.2 加密即时通讯中枢 (E2EE ChatView)

  • 端到端对称加密 (AES-256-GCM)：文字、地理定位、阅后即焚内容在发出前，通过本地生成的哈希对称密钥加密为不可读的 Base64 乱码，并在设置抽屉中提供“手动密钥轮换（Key Rotation）”触发，保障通信安全。
  • Emoji 物理反应粒子大爆破 (Emote Bomb)：当用户点击表情快捷回馈（如炸弹 💥、爱心 ❤️）时，立即在聊天视窗甚至全屏层级上通过 motion/react 运动引擎，以点击坐标为爆破源，散射出 24-36 个物理碰撞反弹粒子，达到 120 FPS 极速视觉响应。
  • 倒计时阅后即焚 (Burn Timer)：在密聊状态下发送的信息附带 5s/10s 自毁时钟。对方接收阅读后自动开启毫秒级倒计时，到期直接自本地状态数组中彻底剔除并覆盖内存。

2.3 家庭连续监护与搜救指挥中枢 (FamilyCareMonitorPage)

  • 应急搜救派遣模式 (Rescue Core)：监控台配备“危机救援派遣”触发装置。开启后普通看护地图瞬间切换为红黑高亮救援图层，同时可在地图上实时生成并移动搜救车辆、应急发电船、战地救护点等危机单元。
  • Geofences 电子安全围栏：支持在控制台上设定特定看护对象（如“兰州老家老人”、“孩子”）的地理安全半径，围栏越界（Out of Boundary）即时触发系统全局红色告警与刺耳的蜂鸣提示。
  • 模拟半双工对讲 (Walkie Talkie)：通过长按 Speak 键，模拟真实无线电对讲状态，伴随波形图（Waves Canvas）抖动，可发送模拟对讲音频片段，实现看护沟通。

2.4 智能文档与非结构化资产中心 (DocumentCenter)

  • AI Smart Organizer 自动归类：系统扫描导入文档、财务发票或 NDA 合同文件的元数据，自动打上财务、法律、备忘、技术等标签。
  • 高保真预览渲染器 (PDF / Spreadsheet Exif Previews)：内置高仿真发票报销详情、合同盖章戳记预览面板、数码照片高阶 EXIF（光圈、焦距、ISO、机身等）读取面板。
  • GoodNotes 扁平无界草稿手记：允许用户在无限制长画布卡片中记录手写备忘、草稿计划，支持指定多种纯色主题卡片，并自动附加建立时间戳与分类属性。

3. 技术架构设计与数据持久化规范

Section 3: System Specs & Local Storage Persistence

Stellar OS 运行在纯静态 React 19 单页应用环境下，状态通过高阶状态机配合严格的序列化引擎实现 LocalStorage 自动落盘自愈。技术栈各项快照如下表：

模块/机制 数据模型 (Type Signature) 存储与序列化媒介 性能开销与优化指标
地标管理 (Custom Markers) interface CustomMarker { id, lat, lng, title, category, tags... } localStorage.setItem('stellar_custom_markers') 极轻量。Leaflet 坐标点采用 Canvas 渲染，保障 500+ 图层不卡顿。
端到端聊天 (E2EE Messages) interface Message { id, senderId, textEncrypted, isBurned, burnDuration... } localStorage.setItem('stellar_chat_history') 本地端密钥哈希解密，消息流通过 Web 渲染性能防抖缓冲。
对讲与监护 (Care Monitor) interface Geofence { id, centerLat, centerLng, radius, targetId... } 内存局部 Buffer + 应急配置落盘 长距离多边形越界测算采用高效 Haversine 球面距离公式。
非结构资产 (Doc center) interface UserDocument { id, title, type, aiCategory, previewData... } 结构化 JSON 模型预装载 + 离线索引 EXIF 与 OCR 数据内置严格空安全 Fallback ("未知/未提取") 渲染逻辑。

3.1 物理外壳组件规格 (IPhone17ProFrame)

为向全平台用户呈现高度逼真的移动端操作体验，应用整体包裹在由 IPhone17ProFrame.tsx 渲染 of 3D 物理直角外壳中，它提供：

  • 高灵敏动能灵动岛 (Dynamic Island)：支持在收到加密即时消息、Geofence 围栏警报、或者对讲机长按时，灵动岛自动横向拉伸变宽，播放平滑的通知波形。
  • 极致微距直角框（Meta Line Base）：采用 1px 高精度钛金属色拉丝边框，两侧配备物理按键反馈。

4. Google AI Studio 建设重构与编译纠错全景日志

Section 4: Complete Dev Logs & High-Priority Compilation Fixes

在 Stellar OS 的数轮核心版本迭代升级中，开发团队借助 Google AI Studio 强大的代码审查、分析与智能重构，处理了多项高危 React 19 崩溃、TypeScript 强校验以及地图底座重叠等难题。以下为最关键的 4 轮构建与纠正日志历史底稿：

🔥 构建日志 1: 消除 React 19 "Expected Static Flag" 编译硬崩溃漏洞 严重阻塞
缺陷定位组件: src/components/FamilyCareMonitorPage.tsx, GoodNotesNoteModal.tsx // 错误码: REACT-19-ERR-0491

起因分析：原代码在上述组件的顶部，通过 if (!isOpen) return null; 进行了提前退出（Early Return）。在 React 19 底层编译器规范下，当组件在 isOpen === false 的早期状态中跳过了后续声明的 useState、useEffect 等核心钩子时，严重违背了 React 的 Hook 声明流绝对顺序一致原则。React 19 编译器在生产构建中抛出不可逆的 Expected static flag was missing 编译阶段和运行阶段双崩溃。

修复与重构：团队配合 Studio 彻底重构了这两个大流量高频组件的生命周期。将所有 useState、useRef、useEffect 统一提至组件的最前端完成实例化注册。仅在返回 JSX 的最终渲染阶段才对 isOpen 进行拦截返回。彻底根治了由于 React 19 严格渲染机制引起的断流式报错，构建成功率拉升至 100%。

💡 构建日志 2: 解决 Map 标签命名空间与原生 JS Map 构造冲突 编译警告
缺陷定位组件: src/components/SlippyLeafletMap.tsx, MapView.tsx // 模块: 省市二级自动空间聚类

起因分析：在引入谷歌地图组件 @vis.gl/react-google-maps 相关的 Map 标签作为图层命名空间后，在同文件作用域内，原生 JS 提供的 new Map() 数据集合对象被编译器隐式遮蔽。当进行自适应空间多级聚类（根据经纬度聚合兰州等各地区地标）时，系统抛出 Map is not a constructor 崩溃。

修复与重构：将所有自适应空间地标聚类、多维图层遍历里的 globalThis.Map 实例化代码统一变更为全局明确的 globalThis.Map()，避开了任何在 JSX 作用域下的组件类型污染，不仅通过了编译，更将大容量地标在 Leaflet 上的聚合性能损耗降低了 40%。

🔧 构建日志 3: 解决看护控制台遮盖主导航与点击失效缺陷 完美解决
缺陷定位组件: src/App.tsx, TopBar.tsx, BottomNav.tsx, FamilyCareMonitorPage.tsx // 模块: 核心布局

起因分析：用户反映进入 Continuous Care 页面（家庭守护舱）后，由于该页面属于全屏级绝对定位（Absolute Page），其 z-index: 30 属性与原本也设置为 z-30 的主导航栏 TopBar 和底部选项卡 BottomNav 产生了点击穿透或遮蔽。用户在守护看护模式下，无法点击顶部的返回按钮或切换底部选项卡。并且由于缺少路由连通性，导致页面操作陷入孤岛。

修复与重构： 1. 将主骨架的 TopBar 与 BottomNav 的 Z-Index 分层全部调配至最上层的 z-50。 2. 重构了 TopBarProps，使其能够支持并感知 isFamilyCareOpen。在监护舱打开时，顶层导航自动渲染优雅高反差的 「返回」 箭头按钮（替换原菜单图标），并更新标题为“家庭守护舱”。 3. 在 BottomNav 以及 App.tsx 的选项卡切换逻辑中，加入了当标签页切换时自动解除看护状态的钩子，彻底解决了无法退出的阻塞性 Bug。

⚙️ 构建日志 4: EXIF 属性空安全与课程日程 TS 类型接口对齐 类型安全
缺陷定位组件: src/types.ts, src/components/DocumentCenterModal.tsx // 错误: TS-Property-Not-Exist

起因分析：在扩充文档中心的非结构化资产（摄影单据、发票信息等）时，引入了针对数码摄影 EXIF 参数的读取机制。但在部分模拟数据或没有图片的草稿备忘中，EXIF 的部分元数据为空（Null/Undefined）。由于 TS 强校验没有做好接口可选属性约束，生产打包抛出类型编译硬报错。

修复与重构：在 types.ts 中细化了 exif 数据结构，提供 ? 可选标识，并在 DocumentCenterModal 文件渲染中使用完美的 previewData?.exif?.camera ?? "未知设备" 空指针容灾策略，使得即使没有任何传感器照片的小微资产卡片也能端庄、安全地呈现基础元数据。

5.1 导出为 PDF 文档的最佳推荐设置

为保证获得最高质量、文字无任何重叠或乱码的高清晰度 PDF 电子版本，请点击顶部的「直接导出 PDF」按钮。在弹出的系统打印及保存面板中，执行以下配置调整：

  1. 目标打印机 / 导出选项：选择 另存为 PDF (Save as PDF)。
  2. 页面范围：选择 全部 (All)。
  3. 纸张尺寸：选择 A4。
  4. 边距 (Margins)：为了保证排版完全端正，强烈推荐选择 "无" (None) 或者是 "默认"。
  5. 选项 (Options)：勾选 背景图形 (Background graphics)，以确保精美的表格斑马线和重点高亮 Badges 能在 PDF 中完美渲染出 Facebook Blue 色彩。

通过此方式生成的 PDF 完全为矢量文字排版，无论是阅读、存档、还是进行多终端流转，均能确保卓越的高保真精细度与最纯粹的直角学术质感。
