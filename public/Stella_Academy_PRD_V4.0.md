## 1. 产品概述

### 1.1 产品名称
**Stella 学海星图（Academy Star Atlas）**

### 1.2 产品定位
学海星图是 Stella 主宇宙中的一个官方垂直星球，面向高校教师、学生、辅导员及院系管理者，提供基于地图与定位能力的大学课程与学业管理服务。它将每一堂课抽象为一座“灯塔”，将一学期课程连接为一条“航线”，将专业与院系构建为“星座”与“星区”，形成真实可交互的学术星图。

### 1.3 产品目标
- **解决痛点**：解决高校传统考勤耗时、代签、资料散落、过程性评价难、课堂互动低、跨班级管理复杂等痛点。
- **高精定位**：利用 Stella 的地图与定位能力，实现自动化签到、未到学生追踪、到课率实时计算。
- **沉浸体验**：通过星球化设计，为教师和学生提供沉浸式教学与学习体验。
- **双向激励**：建立教师与学生双身份成就体系，提升教学与学习积极性。
- **多维对比**：形成院系、学校、跨校同专业的多层次数据对比，推动教学透明化与良性竞争。
- **设计哲学**：严格遵循 Facebook 设计语言：平面文字 + 图标 + 线条，无卡片式结构。

### 1.4 产品 Slogan
> **“每一堂课，都是一座灯塔；每一学期，都是一条星座。”**

## 3. 总体架构：主宇宙 + 星球容器

### 3.1 架构概念
Stella 主产品为“地图社交宇宙”，其中包含多个星球。每个星球是独立的垂直世界，拥有自己的世界观、身份体系、功能模块和交互规则。学海星图是其中一个官方垂直星球。

```
Stella 主宇宙
├── 主地图（日常社交、位置分享）
├── 主身份（Stella Citizen）
├── 主消息系统
├── 主好友关系
└── 星球容器
    ├── 🌌 学海星图（大学课程管理）
    │   ├── 星球身份：教师 / 学生 / 辅导员 / 管理者
    │   ├── 星图地图：灯塔、航线、星座
    │   ├── 课程系统：排课、签到、资产库
    │   └── 成就体系：教学勋章 / 学业星徽
    └── 🪐 其他星球（未来拓展）
```

### 3.2 关键原则
- **主身份不变，星球身份叠加**：用户始终是 Stella Citizen，进入学海星图后获得星球身份，两者并存。
- **数据隔离，入口统一**：星球内数据不影响主系统社交流；主系统仅提供入口、通知、账号基础能力。
- **星球即世界**：进入星球后呈现完整学术星图地图，而非功能列表。

## 4. 身份与账号体系

### 4.1 身份层级

| 层级 | 名称 | 说明 |
| :--- | :--- | :--- |
| **L0** | Stella 主身份 | 用户注册 Stella 时的基础地理社交身份 |
| **L1** | 星球身份 | 学海星图内角色：学生（星航者）、教师（领航员）、辅导员（星区守护者）、管理者（星系管理员） |
| **L2** | 组织身份 | 具体学校/院系/班级/课程所属身份 |

### 4.2 身份激活流程

```
点击学海星图星球
→ 弹出身份激活引导（全屏页面，非卡片）
→ 选择身份类型：学生 / 教师 / 辅导员 / 管理者
→ 输入学校、院系、学号/工号
→ 系统发送验证码/邀请码到学校邮箱或手机
→ 验证通过后，自动匹配学籍/教职信息
→ 激活成功，进入星图主界面
```

- **学生**：需输入学号 + 学校邀请码，或通过学校教务系统 OAuth 授权。
- **教师**：需输入工号 + 学校/院系邀请码，或由院系管理员后台添加。
- **辅导员**：需学校管理员授权，自动获得院系管理权限。
- **访客模式**：未激活用户可浏览公开信息，无法签到和参与课程。

### 4.3 身份切换逻辑
- 主界面点击“星球”Tab → 选择“学海星图” → 进入星球。
- 星球内顶部显示当前星球身份名片，主身份头像缩小显示在右上角。
- 用户可随时点击“← 主宇宙”退出星球。
- 若用户拥有多重身份（如学生+助教），顶部身份栏可切换，页面功能与权限实时更新。

## 5. 核心功能模块

### 5.1 学籍与班级库
由星系管理员和星区守护者维护，是学海星图的基础数据层。

**数据层级：**
```
大学（星系）
├── 院系（星区）
│   ├── 专业（星座）
│   │   ├── 年级
│   │   │   ├── 行政班
│   │   │   │   ├── 学生
```

**辅导员操作：**
1. 批量导入学生名单（学号、姓名、专业、年级、班级、手机号）。
2. 设置班级负责人/班长。
3. 分配学生到具体行政班。
4. 设置特殊标签（如“重点关注”“学业预警”）。
5. 向授课老师推送班级名单。

**数据来源：**
- 手动导入 Excel / CSV。
- 对接学校教务系统 API。
- 学生自行加入后辅导员确认。
- 从上一学期自动复制名单。

### 5.2 课程创建与灵活授课对象
**核心变化：不再设置课程人数上限。**
授课老师创建课程时，不填写“总人数”，而是选择“授课班级/学生名单”。人数由所选名单自动计算，支持动态变化。

**创建课程流程：**
1. 填写课程名称、开课院系、专业、年级。
2. 选择授课对象：从行政班中选择 / 从辅导员推送名单中选择 / 手动添加个别学生。
3. 系统自动计算应到人数。
4. 设置课程基础参数：学期周数、每周上课次数、上课时间、教室、默认签到半径、默认最低停留时长、默认聊天模式。
5. 设置课程资产库章节结构（可选）。
6. 创建成功，系统自动生成排课计划。

**每堂课的独立名单：**
每次灯塔可单独调整应到名单，支持合班课、实验分组、补课、停课等场景。

### 5.3 智能排课引擎

**排课参数：**

| 参数 | 说明 |
| :--- | :--- |
| **学期起始日期** | 第 1 周周一的日期 |
| **学期周数** | 一学期总周数（如 16 周） |
| **每周上课次数** | 每周上课次数（如 2 次） |
| **单次课时长** | 一节课时长（如 90 分钟） |
| **上课时间** | 星期几第几节（如 周二 14:00-15:35） |
| **上课地点** | 教室名称与物理坐标（如 逸夫楼 302） |
| **授课对象** | 每次课参加的班级/名单 |
| **单双周规则** | 是否需要单双周轮换 |
| **假期/调课** | 自动跳过节假日 |

**排课逻辑：**
1. 系统根据学期周数和每周上课次数自动生成全部灯塔。
2. 自动跳过国家法定节假日。
3. 老师可对任意灯塔进行调课、补课、停课。
4. 每个灯塔自动继承课程默认签到参数，可单独修改。

**课程图谱智能匹配：**
系统内置各专业培养方案，老师可选择“从培养方案导入”，自动填充课程名称、开课院系、周学时、总学时等，减少录入。

### 5.4 灯塔签到与考勤机制

#### 5.4.1 签到状态定义

| 状态 | 判定条件 | 到课率计次 |
| :--- | :--- | :---: |
| **有效到场** | 进入灯塔半径内，且停留 ≥ 最低时长（默认 40 分钟） | **1 次** |
| **迟到** | 开课后进入半径，且停留 ≥ 最低时长 | **0.5 次** |
| **早退** | 进入半径，但停留 < 最低时长 | **0 次** |
| **未到场** | 从未进入灯塔半径 | **0 次** |
| **已请假** | 提前提交请假申请，审批通过 | **不计入应到** |
| **停课** | 该次灯塔被取消 | **不计入应到** |

#### 5.4.2 签到流程
1. 开课前 15 分钟，系统向应到学生推送定位请求。
2. 学生开启定位，进入 Stella 地图。
3. 学生进入灯塔坐标半径内，系统开始计时。
4. 学生头像自动进入到场目录，地图位置隐藏（保护隐私）。
5. 学生停留满最低时长，标记“有效到场”。
6. 课程结束后，系统自动统计签到结果。
7. 老师/管理员/辅导员可对异常情况人工修正。

#### 5.4.3 未到学生追踪
- 管理端地图只显示**未到学生**实时位置红点。
- 显示姓名、头像、当前地理位置、距离灯塔路程、最后定位时间。
- 已到场学生不在地图显示。
- 辅导员/教导员可查看本院系未到学生，一键提醒/拨打电话。

#### 5.4.4 点亮指数
$$\text{点亮指数} = \frac{\text{有效到场人数}}{\text{应到人数}} \times 100\%$$
*(注：应到人数 = 本次灯塔应到名单人数 - 已请假人数)*

| 点亮指数 | 亮度表现 | 视觉状态 |
| :--- | :--- | :--- |
| **100%** | 光芒四射 | 耀眼全勤金光 ✨ |
| **90% - 99%** | 高亮 | 恒常亮蓝光 🌟 |
| **70% - 89%** | 中等 | 标准青蓝光 💡 |
| **50% - 69%** | 微光 | 微弱昏黄光 🕯️ |
| **< 50%** | 暗淡 | 警告暗红光 ⚠️ |

#### 5.4.5 到课率计算
$$\text{到课率} = \frac{\text{有效到场灯塔数} + 0.5 \times \text{迟到灯塔数}}{\text{应出勤灯塔总数}} \times 100\%$$
*(注：应出勤灯塔总数 = 学期内该课程灯塔总数 - 停课灯塔数 - 已请假灯塔数)*

**示例**：线性代数一学期 16 周，每周 2 次课，共 32 个灯塔。停课 2 次，学生请假 1 次，应出勤 = 29 次。学生有效到场 26 次，迟到 2 次，到课率 = $(26 + 2 \times 0.5) / 29 \approx 93.1\%$。

### 5.5 课程资产库
任何人在课程内发布的文档、图片、文件，自动归入课程资产库。按章节、类型、上传者、关联灯塔自动归档。

- **资产类型**：课件、作业、试卷、参考书、通知、课堂录屏/录音、讨论附件。
- **权限控制**：
  - 老师/管理员上传：默认全员可见。
  - 学生上传：需老师审核后公开，默认仅本人可见。
  - 监督员上传：本小班可见。
- **版本管理**：同一文档新版本上传时，自动保留历史版本，学生始终看到最新版本。
- **期末归档**：学期末一键生成课程档案包，包含全部课件、考勤记录、作业成绩、课程报告。

### 5.6 聊天信箱与课堂互动
- **信件机制**：新发言生成“信件”，进入信箱列表。点击信件进入发言气泡模块，所有回复集中展示，不散落到时间线。
- **互动能力**：支持回复、引用、@成员、表情回应。
- **可见模式**：无声 / 群主可见 / 两人群主可见 / 全员可见。
- **课堂增强**：
  - 知识点关联：发言可关联资产库课件。
  - 匿名提问：学生可匿名发问。
  - 快速投票：老师发布投票，学生点击回复。

### 5.7 数据统计与跨校对比

#### 5.7.1 个人到课率
按学期、课程分别统计，支持查看每门课到课率、迟到/早退/请假次数、学业健康度雷达图。

#### 5.7.2 班级/小班对比
同一课程内各小班到课率对比，辅导员可查看本院系各班级到课率。

#### 5.7.3 院系横向对比
以院系为单位，展示各课程到课率、灯塔亮度、文档活跃度等指标。

#### 5.7.4 同专业跨校对比
在用户授权且数据脱敏前提下，形成全国高校相同专业数据对比。

$$\text{专业星群指数} = \text{到课率}\times 40\% + \text{灯塔亮度}\times 30\% + \text{课程完成度}\times 20\% + \text{教学活跃度}\times 10\%$$

### 5.8 游戏化与身份名片

## 8. 异常与边界

### 8.1 定位与隐私
- 仅在开课前 15 分钟至课程结束期间获取定位。
- 学生可选择“仅课程期间共享位置”。
- 未到学生位置仅教师、辅导员、班级守护者可见。

### 8.2 请假审批
- 学生提前提交请假申请，附证明材料。
- 老师/辅导员审批通过后，该生不计入应到人数。

### 8.3 调课/停课
- 调课保留原签到记录，新时间重新签到。
- 停课不计入到课率。

### 8.4 数据安全
- 跨校对比数据脱敏，仅展示匿名或授权后的聚合数据。
- 个人数据仅本人及授权管理人员可见。
